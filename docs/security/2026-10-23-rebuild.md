  3.11 variant. Always pull it again at rebuild time; the tag is mutable.
- Refresh Debian packages and require `ca-certificates >= 20250419+deb13u1`.
  Rebuild aborts if that update is unavailable or affected roots remain trusted.
- Bootstrap pip 26.2.2 from the exact wheel URL/SHA256 published by Python's
  security advisory. No blind old-pip upgrade or disabled TLS verification.
- Remove unused base-image setuptools (published version 79.0.1 has an advisory
  fixed in 83.0.0). Audit the actual image too; the published base is not proof
  of what is installed in a deployed image.
- Update direct dependencies to cryptography 50.0.2, google-api-python-client
  2.201.0, google-auth 2.62.0, google-auth-oauthlib 1.5.0. Lock all 25 runtime
  packages with hashes, including certifi 2026.10.23. Inputs are requirements.in.
- Check effective default SSL trust (IMAP/urllib), Debian CA file, certifi,
  pip's vendored certifi, Requests, and httplib2 (Gmail). Check affected root
  fingerprints, nonempty stores, TLS verification, and Requests overrides.
  This is an offline trust-anchor check, not a live handshake or a full PKI audit.
- Add a Docker build-context allowlist to exclude .env, state, Git metadata and
  local environments. Application logic, migrations, Compose and ports unchanged.

## Future OCI rollout — do not run until deployment is approved

Run from the **existing OCI clone and Compose project**, using its normal
privileges and exact existing project name. Do not clone into a new directory or
change `Y2G_DATA_PATH`, `SQLITE_PATH`, `APP_MASTER_KEY`, project name or secrets.
The bind mount is `${Y2G_DATA_PATH:-./data}:/data`; preserve its actual source,
including the SQLite DB/WAL/SHM and encrypted credentials, together with the
matching master key and original .env. An empty/different DB can replay mail;
a different master key cannot decrypt existing credentials.

First check `git status --short` locally and stop if there are changes; do not
reset or overwrite them. In this first-time branch example, set PATCH_COMMIT to
the full tested commit SHA in the handoff. If the branch already exists, use
`git switch security/emsign-trust-refresh` instead of creating it.

```sh
set -eu
PATCH_COMMIT='REPLACE_WITH_FULL_TESTED_COMMIT_SHA'
git fetch origin security/emsign-trust-refresh
git switch --track -c security/emsign-trust-refresh origin/security/emsign-trust-refresh
git pull --ff-only origin security/emsign-trust-refresh
test "$(git rev-parse HEAD)" = "$PATCH_COMMIT"

# Keep shell history/output free of secrets. Do not print compose config or .env.
umask 077
stamp=$(date -u +%Y%m%dT%H%M%SZ)
backup_dir="$HOME/yahoo2gmail-backup-$stamp"
mkdir -m 700 "$backup_dir"
service=yahoo2gmail-forwarder
cid=$(docker compose ps -q "$service")
test -n "$cid"
old_image=$(docker inspect --format '{{.Image}}' "$cid")
data_source=$(docker inspect --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Source}}{{end}}{{end}}' "$cid")
test -n "$data_source" && test -d "$data_source"
old_tag="yahoo2gmail-rollback:$stamp"
docker image tag "$old_image" "$old_tag"
printf 'services:\n  yahoo2gmail-forwarder:\n    image: %s\n    pull_policy: never\n' "$old_tag" > "$backup_dir/rollback.yml"
cp -p .env docker-compose.yml "$backup_dir/"
git rev-parse HEAD > "$backup_dir/candidate-commit.txt"

# Stop the sole writer before taking a consistent whole-directory state backup.
docker compose stop "$service"
tar -C "$data_source" -cpf "$backup_dir/data.tar" .
# Abort on any backup error; use appropriate read privileges if needed.
test -s "$backup_dir/data.tar"

candidate_image="yahoo2gmail-security:$stamp"
printf 'services:\n  yahoo2gmail-forwarder:\n    image: %s\n    pull_policy: never\n' "$candidate_image" > "$backup_dir/candidate.yml"
docker compose -f docker-compose.yml -f "$backup_dir/candidate.yml" build --pull --no-cache "$service"
# No production environment, credentials, volumes or network in these checks.
docker run --rm --network none --entrypoint python "$candidate_image" /app/scripts/verify_trust.py
docker run --rm --network none --entrypoint python "$candidate_image" -m pip check
docker run --rm --network none --entrypoint python "$candidate_image" -m pip list --format=freeze > "$backup_dir/python-packages.txt"
docker run --rm --network none --entrypoint sh "$candidate_image" -c 'python --version; dpkg-query -W ca-certificates openssl libssl3t64'
```

Use a current trusted image scanner on that exact candidate image (for example,
`trivy image --scanners vuln "$candidate_image"`) and audit its exported Python
inventory with patched audit tooling. Review findings before proceeding. Neither
scan was possible here. Store the resulting image ID/digest and scan evidence.
If build/trust/audit gates fail, keep the candidate stopped, investigate, and
restart the tagged old image only as an explicit rollback decision.

After all gates pass and deployment is authorized:

```sh
docker compose -f docker-compose.yml -f "$backup_dir/candidate.yml" up -d --no-build --force-recreate "$service"
docker compose ps "$service"
# Verify running image matches candidate, and mount still equals data_source.
cid=$(docker compose ps -q "$service")
docker inspect --format '{{.Image}}{{range .Mounts}}{{if eq .Destination "/data"}} {{.Source}} -> {{.Destination}}{{end}}{{end}}' "$cid"
docker image inspect --format '{{.Id}}' "$candidate_image"
```

Privately inspect normal application health/logs for migration/crypto errors,
OAuth refresh and watcher progress. Keep original delivery/admin settings. Do not
use the real-mail helper as a smoke test; observe ordinary operation only after
authorized restart. There is no application healthcheck in this Compose file.
Admin is documented disabled by default; published 8787 has no app auth. This
patch does not change its exposure or host firewall. Host Ubuntu trust updates
are a separate task; updating container trust does not update the OCI host.

## Rollback

Keep the old tagged image and protected backup until the new build is accepted.
The old image may retain these vulnerabilities: rollback restores availability,
not remediation. From the same project/clone with original Compose/.env and
master key, run only when rollback is authorized:

```sh
docker compose -f docker-compose.yml -f "$backup_dir/rollback.yml" up -d --no-build --force-recreate yahoo2gmail-forwarder
```

This patch changes no migrations. Retain the **current** /data when reverting the
image; restoring an older DB after new mail was processed can replay messages.
Only restore the cold backup with the service stopped if state recovery is
actually required, preserving ownership/permissions and the matching original
key. Never run `down -v`, delete /data, rotate the master key, prune the tagged
rollback image, or overwrite .env as part of an ordinary rebuild.
